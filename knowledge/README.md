# knowledge — 모델별 권장 구조 (머리)

node-smith의 **코드는 "손"** 이다 — 캔버스에 노드를 생성·연결·배치할 뿐, *어떤* 노드를
*어떻게* 이어야 하는지는 모른다. 이 폴더가 그 판단 재료(**"머리"**)를 담는다.

## 왜 코드가 아니라 데이터인가

모델별 권장 구조(어떤 로더·샘플러·전용 노드)는 **모델이 업데이트되면 계속 바뀐다.**
이걸 파이썬/JS 로직에 하드코딩하면 모델 하나 늘 때마다 코드를 고쳐야 하고 도구가 비대해진다.
그래서 지식을 **데이터 파일(md + json)** 로 이 폴더에 둔다:

- 코드(`__init__.py`·`js/`·`mcp_server.py`)는 지식이 바뀌어도 **그대로**다.
- 모델이 업데이트되면 **이 폴더의 파일만** 고치면 된다(프로그래밍 불필요).
- node-smith가 **혼자서도(self-contained)** 권장 구조를 안다.

## 폴더 형식

```
knowledge/
├─ README.md          ← 이 파일
└─ <model>.md         ← 모델별 설명서: 권장 노드 구조·값·함정·프롬프트 패턴
```

> 검증된 워크플로우 JSON("정답지")을 함께 두고 싶으면 `<model>.md` 옆에 나란히 두면 된다.
> (이 공개 저장소에는 md 지식만 담고, 실제 워크플로우 파일은 각자 환경에서 채운다.)

## 어떻게 쓰이나

에이전트(Claude)가 "○○ 모델로 워크플로우 만들어줘"를 받으면:

1. 해당 모델의 `<model>.md`를 읽어 **권장 구조를 판단**한다(머리).
2. `edit_graph`로 캔버스에 **실제로 조립**한다(손).

## 출처 원칙 (추측 금지)

여기 담는 구조는 **검증된 것만** 넣는다:

- **직접 만들어 결과를 확인한 워크플로우** — 실제 생성으로 동작을 검증한 구조.
- **모델별 검증 지식** — 로더·전용 노드·샘플러 값 등.

추측으로 채우지 않는다. 모델이 바뀌어 구조가 달라지면 이 폴더를 갱신한다.
